# PAL Engine: decision log

Every judgment call made while building PAL Engine, newest at the bottom. "Spec" means the
Claude Code build prompt; "TBD" means the reference "Technical Build Document".

| id | decision | why | revisit when |
|----|----------|-----|--------------|
| D-001 | **Built in `fortheeco/RigAfrica` on `claude/pal-engine-backend-tluaxv`, not in the ECO platform repo.** Only schema-independent parts are built: `packages/pal-core`, `config/`, `eval/`, `ml/`, `docs/`. No migrations and no edge functions yet. | RigAfrica is a 2023 static site plus a Django branch and has no ECO tables. The Lovable-synced repo `fortheeco/eco-civic-console` could not be attached: the session's GitHub credential has no access to it. Spec §9 says STOP for schema-dependent work. | Access to `eco-civic-console` is granted. The directories are self-contained and move across unchanged. |
| D-002 | Tests use `node:test` with Node ≥22.18 built-in type stripping. `pal-core` has **zero runtime dependencies**. Imports use explicit `.ts` extensions. | One implementation runs unchanged in Node (tests, eval) and Deno (edge functions). `erasableSyntaxOnly` is on, so there are no enums or namespaces. | — |
| D-003 | TypeScript pinned to `~5.9.3`, not 7.x. | 7.x is the native-compiler rewrite and some flags changed. Stability first. | When eco-civic-console's toolchain moves. |
| D-004 | Age in months = ms / 2 629 800 000 (365.25/12 days). | It's an integer, so an event dated exactly N months back has age exactly N. That makes the 18-month half-life test exact rather than approximate. | civic_score uses a different month definition (unverified: civic_score code not visible). |
| D-005 | C uses a **weighted** count of distinct claimed items. Unvalidated-language items weigh `unvalidated_language_weight` (0.5). | Spec §5.4 says to multiply weight by 0.5, and C is the only place a claimed weight enters. | — |
| D-006 | Claimed items with no `axis_hint` or no sector don't count toward any C. They still feed matching text (offers/needs). | C is defined per axis and sector. Guessing an axis would be inference beyond the evidence. | — |
| D-007 | `extraction.validated_languages` defaults to `[en]`. | The spec names sw, pcm and yo as unvalidated, and English is the baseline. The eval language gate controls promotion. | The first language-gate run. |
| D-008 | Rising baseline = latest `pal_profile_history` snapshot at or before now−90d. **If there's none, V is recomputed as of now−90d from evidence.** | Without the fallback nobody can be Rising during a place's first 90 days. The as-of value is exact because evidence is timestamped. | — |
| D-009 | State is computed per (sector, axis). Readiness filters "not Dormant" using the state of the counted role's axis. | The API exposes state "per sector and axis" (spec §7). | — |
| D-010 | At most two roles per sector (primary plus one). | The spec says "a second role is added". | — |
| D-011 | Added `matching.candidates_per_role` (15): shortlist per role before enumerating trios. | Bounds trio enumeration to 15³. | — |
| D-012 | The config validator is strict: unknown keys are rejected, `verification_multiplier.unverified` must be 0, `purge_days` ≤ 30, matching weights sum to 1, and instance overrides are validated after merging. | The stingy and purge rules can't be configured away, and typos can't silently fall back to defaults. | — |
| D-013 | Events dated after `now` are ignored. `quality` is clamped to [0,1]; null quality = 1.0. | The spec defaults to 1.0 when the field is missing. | — |
| D-014 | Added config keys not listed in spec §4: `model_version`, `extraction.*`, `sparks.min_active_verifiers` (1), `fairness.max_median_gap` (15). | Each value comes from the spec text. This keeps them tunable rather than hardcoded. | — |
| D-015 | Signal idempotency key = (source, evidence_ref, type, sector, axis, normalised value). Re-ingesting an `evidence_ref` **replaces** its feature set: features no longer extracted are deleted, changed confidence or weight is updated, identical ones are untouched. The DB also needs a unique index on `(person_id, idem_key)`. | "Re-ingesting the same evidence_ref updates, not duplicates" must still hold when the LLM rewords a value. | — |
| D-016 | The protected-attribute lexicon is deliberately broad. It includes **gender terms** (e.g. "women in agribusiness" is rejected) and ethnic names that collide with place names (Edo, Meru). It's checked on `type`, `value` and `sector` before anything else, so protected-looking types count as `protected_attribute`, not `unknown_type`. | The spec says never read or infer protected attributes, and gender is only ever optional self-report. A false reject costs one claimed item; a false accept profiles someone. | Regional reviewers should review the list per language before launch. |
| D-017 | Evidence refs that look like DMs or private groups (`/messages/`, `/direct/`, `/groups/`, WhatsApp, private Telegram links) are rejected as `private_source`. The ref must be an `https` URL or a plain post-id token. | Defence in depth for "never read DMs or private groups". The connector also enforces this through OAuth scopes. | — |
| D-018 | Consent state for a (person, source) is its **latest** consent row. A re-grant after a revoke allows ingest again. The purge deletes every derived row of a revoked (person, source) on the **first** job run, rather than waiting for day 30. Rows still present after the deadline are reported as `overdue`. | 30 days is an upper bound, not a delay. | — |
| D-019 | Handle proof (OAuth completion or bio-code) is required for `oauth` and `export_upload` sources, not for `self_declared`. Bio codes are `ECO-` plus 8 characters from an unambiguous alphabet. Randomness is supplied by the caller (`crypto.getRandomValues`). | Spec §2.3. Keeps core pure. | — |
| D-020 | Contact matching returns only existing members' ECO ids plus a dropped **count**. Alias normalisation is a `STUB` until eco-id-resolve's normaliser can be imported. Phone normalisation takes the calling code from the caller (instance config). | Spec §2.4. eco-id-resolve isn't visible (D-001). | When eco-civic-console is accessible. |
| D-021 | **Spec tension (flagged):** the default readiness targets (5/10/8) are at or below `k_min` (10), so an exact TR would reveal sub-k role counts. Resolution: a public cell shows the exact TR and uncertainty **only when all three role counts ≥ k_min**. Otherwise it shows `tr_band` (0-25/25-50/50-75/75-100) and `uncertainty: null`. Role counts below k_min are always banded. `missing_roles` is ordered by gap but carries no gap size. | Spec §2.7 and the k-anonymity acceptance test. With the defaults this means nearly every pilot cell shows a band. | **Product decision needed**: raise the targets, lower k_min, or accept banded TR during the pilot. |
| D-022 | The public map is one cell per (place, sector) with **no cross-cell totals** (no place-wide or instance-wide counts). A cell's public form depends only on that cell, so any filtered response is an exact subset of the unfiltered one. That's what defeats differencing across sector filters. | Spec §8, k-anonymity test. | — |
| D-023 | Readiness mean confidence is averaged over **distinct** counted people. A person counted in two roles contributes their mean confidence once. `low_population` is true when distinct counted people < k_min. | The spec says "counted people", not role slots. | — |
| D-024 | `Place` is data (`pal_places`: id, instance_id, name, place_type, target_profile, parent_id). Nairobi sub-counties are places with `parent_id` set to Nairobi county. | No hardcoded places (spec §2.9). | — |
| D-025 | A candidate is eligible for a role when B on that axis in the Spark's sector is > 0, so claimed-only people **can** be proposed. Their explanation shows V = 0, trust = 0, no verified trust drivers, and the note "claimed signals only". | The spec says matching uses V + 0.4·C, so claims are meant to count in matching. The stingy rule is about labelling, and it's enforced in the explanation payload. | If stewards want verified-only matching, add `matching.min_verified`. |
| D-026 | Cosine similarity is clamped to ≥ 0. Trust = confidence × V/100. Availability = share of the Spark window covered by the union of declared windows; **none declared = 0**. Diversity = (distinct clusters − 1)/2. Clusters are the declared org/community, case- and space-normalised; no org means the person is their own cluster. | These are the spec formulas made concrete. | Stage B replaces clusters with graph communities. |
| D-027 | Exclusions: revoked consent, a declared conflict with the Spark (person-wide), an open dispute **on the role's axis in that sector** (role-specific), and pairwise declared conflicts between trio members. | "Open dispute on relevant evidence" means the axis that would be used. | — |
| D-028 | Trio enumeration takes the top `candidates_per_role` per role by partial score (fit, trust and availability), then scores full trios. Trios returned may share members. | Bounded cost. Overlapping trios give stewards real alternatives for one slot. | — |
